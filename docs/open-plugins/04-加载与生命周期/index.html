    04 · 加载与生命周期：插件如何被"活"起来¶

    契约定义清楚后，核心问题就是运行时：插件包怎么被识别、解压、加载成库、实例化成对象，并跟随主程序的生命周期启停。本章以 PluginsManagerImpl 为主角，把整条流水线讲清楚。

    4.1 入口：SetupPM 与 ShutdownPM¶

    manager 的生命周期由两个 C 接口打开与关闭（plugins_manager/plugins_manager.hxx）：

    PluginsManager *SetupPM(const char *plugins_dir, CreateWebView_t CreateWebView,
                        const char *domain, const char *tmp_dir = nullptr);
void ShutdownPM(PluginsManager *pm);

    参数语义：

    参数 含义
    plugins_dir 插件搜索目录（存放 *.zip 插件包）
    CreateWebView 创建 wxWebView 的函数指针（平台差异由宿主注入）
    domain 主程序翻译名（i18n 用）
    tmp_dir 插件解压临时目录；默认系统临时目录；调试时可直接指向搜索目录

    构造时（PluginsManagerImpl 构造函数）会一次性搭好内部环境：

    router_ = std::make_shared<EventRouter>();
fs_handler_ = std::make_shared<MemoryFSHandler>();
wxFileSystem::AddHandler(fs_handler_.get());              // 挂内存文件系统
wxXmlResource::Get()->InitAllHandlers();                  // 初始化 XRC 处理器
wxXmlResource::Get()->AddHandler(new WebviewHandler(...)); // 注册 wxWebView 的 XRC 处理器
package_visitor_ = [](const wxString &package) { return true; }; // 默认包访问器

    4.2 流水线总览¶

    从"目录里的 zip"到"可用的插件实例"，manager 分三个阶段，由生命周期事件驱动（EmitEvent）：

    ① 包识别与校验   CheckPackage()
      │  遍历 plugins_dir/*.zip，逐个签名+MD5 校验
      ▼  通过者进入 plugin_packages_
② 解压与装载     EmitEvent(kEventInitByApp) → LoadPlugins()
      │  UnzipAll → TraverseDirectory 找 plugin_* 库
      ▼  动态库 LoadLibrary + 静态库批量注册 → libraries_
③ 实例化与启动   EmitEvent(kEventFinishedByGUI) → CreateInstances()
      ▼  多轮依赖解析 → SetupPlugin → instances_ → Start()
      ▼
   可用插件实例集

    4.3 阶段一：包识别与校验（CheckPackage）¶

    CheckPackage() 遍历插件目录下所有 *.zip，对每个包做两件事：

    1. 包访问器过滤：package_visitor_(filename) 返回 false 就跳过（宿主可在上层决定哪些包不加载）；
    2. 完整性与签名校验：CheckPackage_(path)——读取 signature.bin、AES 解密、解析包信息 JSON、再对包内每个 plugin_* 文件比对 MD5（完整流程在第 8 章详述）。
    for (bool cont = pluginsDir.GetFirst(&filename, wxT("*.zip"), wxDIR_FILES);
     cont; cont = pluginsDir.GetNext(&filename)) {
  if (!package_visitor_(filename)) continue;            // 上层拒绝，跳过
  if (!CheckPackage_(zipFile.GetFullPath().utf8_string())) {
    LOG_WARN("check package failed:{}", filename);      // 校验失败仅跳过
    continue;
  }
  plugin_packages_.push_back(filename);                 // 通过才进入待解压列表
}

    关键语义：校验失败的包只是被跳过（continue），不会中断整个 manager 启动。这保证了"某个坏插件不影响其他插件"的健壮性。

    4.4 阶段二：解压与装载（LoadPlugins）¶

    EmitEvent(EventType::kEventInitByApp) 触发 LoadPlugins()，分四步：

    size_t PluginsManagerImpl::LoadPlugins(void) {
  if (!::UnzipAll(plugin_packages_, tmp_dir_)) return 0;   // ① 全部解压到临时目录
  wxDir dir(...);
  std::vector<wxString> plugins;
  if (dir.IsOpened()) TraverseDirectory(..., plugins);     // ② 递归找 plugin_* 库
  // ③ 静态插件：编译期数组 + 运行期 AddStaticPlugins
#if PLUGINS_LIST_SIZE > 0
  auto create_library_array = GetCreateLibraryArray();
  for (int idx = 0; idx < PLUGINS_LIST_SIZE; idx++) {
    if (create_library_array[idx] != nullptr)
      libraries_.push_back(create_library_array[idx]());
  }
#endif
  for (auto create_library_array : static_plugins_)
    libraries_.push_back(create_library_array());          // AddStaticPlugins 注入的
  // ④ 动态插件：逐个 LoadLibrary
  std::ranges::transform(plugins, std::back_inserter(libraries_),
      [](const wxString &fname) -> std::shared_ptr<LibraryBase> {
        if (auto lib = std::make_shared<LibraryShared>();
            lib->LoadLibrary(fname)) return lib;
        LOG_ERROR("Load library {} failed", fname);
        return nullptr;
      });
  // ⑤ 过滤：必须能取到 info 且 plugin_api == 1
  std::ranges::copy_if(tmp_libs, std::back_inserter(libraries_),
      [](const auto &lib) {
        auto info = lib->GetPluginInfo();
        return info != nullptr && info->plugin_api == 1;   // 硬性 API 版本校验
      });
  return libraries_.size();
}

    几个关键点：

    • 解压后递归遍历（TraverseDirectory）在临时目录里找所有符合 IsPlugins（前缀 plugin_ + 平台扩展名）的文件，也就是说插件包内可以有任意目录层级；
    • 静态插件优先于动态插件加入 libraries_，且 LoadLibrary 失败的动态库以 nullptr 占位，最后统一过滤；
    • API 版本校验是加载与否的分水岭：info->plugin_api == 1 才保留（与 PLUGIN_API_VERSION = 1 对应）。

    4.5 阶段三：实例化与启动（CreateInstances）¶

    EmitEvent(EventType::kEventFinishedByGUI)（GUI 初始化完成）触发 CreateInstances()：

    bool PluginsManagerImpl::CreateInstances(void) {
  std::vector<std::shared_ptr<LibraryBase>> libraries;
  std::swap(libraries_, libraries);
  size_t previous_size = 0;
  do {
    previous_size = 0;
    for (auto itr = libraries.begin(); itr != libraries.end();) {
      auto lib = *itr;
      if (InitPlugin(lib)) {            // 依赖满足才初始化
        libraries_.push_back(lib);
        itr = libraries.erase(itr);
        previous_size += 1;
      } else {
        ++itr;                          // 依赖未满足，留在列表等下一轮
      }
    }
  } while (previous_size > 0 && !libraries.empty());   // 多轮直到无进展

  LOG_ERROR_IF(!libraries.empty(), "未解决的循环依赖，剩余库: {}", libraries.size());
  for (const auto &[_, lib] : instances_)
    LOG_ERROR_IF(!lib->Start(), "plugin start failed: {}", lib->Name());
  return !instances_.empty();
}
    • 多轮迭代：每轮把所有"依赖已满足"的插件初始化并移出列表，无法满足的留下等下一轮；直到某轮无进展或列表清空。这正是第 5 章依赖解析的实现载体；
    • 初始化完成的插件统一 Start()（启动失败仅记 LOG_ERROR）；
    • 初始化期间通过 InitPlugin(lib) 逐个执行：检查依赖 → router_->SetPluginName → lib->SetupPlugin(this) → 存入 instances_。

    InitPlugin 的实例化与托管：

    bool PluginsManagerImpl::InitPlugin(std::shared_ptr<LibraryBase> lib) {
  auto info = lib->GetPluginInfo();
  if (info == nullptr) return false;
  for (auto idx = 0; idx < info->dependency_count; idx++) {
    if (!HasPlugin(info->dependency[idx])) {   // 依赖未就绪
      return false;
    }
  }
  router_->SetPluginName(info->name);          // 路由上下文切到当前插件
  if (Anycubic::Plugins::Plugin *instance = lib->SetupPlugin(this);
      instance != nullptr) {
    instances_.emplace_back(
        wxString::FromUTF8(instance->Name()),
        std::shared_ptr<Plugin>(instance, ::delete_plugin<Plugin>)); // 自定义删除器
    LOG_INFO("Init plugin {} success", info->name);
  }
  return true;
}

    注意 std::shared_ptr<Plugin>(instance, ::delete_plugin<Plugin>) 的自定义删除器：析构时调用 plugin->Destroy()（而 Destroy 里插件执行 delete this），保证"插件自销毁"语义被统一管理，同时释放时打印日志。

    4.6 生命周期事件机：EmitEvent¶

    EventType 定义了五个阶段，EmitEvent 在对应时机被宿主调用：

    enum class EventType : int8_t {
  kEventInitByApp   = 0, // 应用程序初始化时触发
  kEventInitByGUI,       // GUI 框架初始化时触发
  kEventFinishedByGUI,   // GUI 初始化完成时触发
  kEventExitByGUI,       // GUI 退出时触发
  kEventExitByApp,       // 应用程序退出时触发
};

    EmitEvent 的实现把每个事件映射到具体动作：

    事件 动作
    kEventInitByApp LoadPlugins()：解压 + 装载所有库
    kEventInitByGUI 设置 i18n 的翻译加载器（wxTranslations::SetLoader）
    kEventFinishedByGUI 一次性 CreateInstances()：实例化 + 启动（用 is_inited_ 防止重复）
    kEventExitByGUI 逆序 Stop() 所有实例 → 清空 router_/instances_/widgets_，重置 is_inited_
    kEventExitByApp 释放 translations_loader_、清空 libraries_ 
    void PluginsManagerImpl::EmitEvent(EventType event) {
  assert(wxIsMainThread());          // 生命周期事件必须在主线程
  switch (event) {
  case EventType::kEventInitByApp: LoadPlugins(); break;
  case EventType::kEventInitByGUI:
    wxTranslations::Get()->SetLoader(translations_loader_); break;
  case EventType::kEventFinishedByGUI:
    if (is_inited_ == 0) { is_inited_ = 1; CreateInstances(); }
    break;
  case EventType::kEventExitByGUI:
    translations_loader_->Clear();
    std::for_each(instances_.rbegin(), instances_.rend(),
                  [](auto &pair) { pair.second->Stop(); });  // 逆序停止
    router_.reset(); instances_.clear(); widgets_.clear(); is_inited_ = 0;
    break;
  case EventType::kEventExitByApp:
    translations_loader_ = nullptr; libraries_.clear(); break;
  }
}

    值得强调的两个设计点：

    1. 主线程约束：所有生命周期事件都 assert(wxIsMainThread())，界面相关（AddWidget、WatchWindow）也要求主线程——这避免了 GUI 操作跨线程的经典事故；
    2. 退出顺序：GUI 退出时逆序 Stop() 插件（后初始化的先停，符合依赖的反向销毁），再清空实例与路由；kEventExitByApp 才释放库本身。

    4.7 窗口面板与虚拟文件系统（宿主能力侧写）¶

    加载之外，manager 作为宿主还给插件提供了"界面 + 资源"能力，这里有两条路径值得记录：

    CreatePanel（按位置 / 按父窗建面板）——核心是把插件给的 XRC 字符串加载进内存文件系统再实例化：

    wxPanel *PluginsManagerImpl::CreatePanel(wxWindow *parent,
                                         const wxString &xrcName,
                                         const wxString &xrc) {
  wxString name = RandomString(16) + ".xrc";
  if (!this->AddFS(name, xrc)) return nullptr;          // 写入内存 FS
  auto result = wxXmlResource::Get()->Load("acmemory:" + name); // 从内存 FS 加载 XRC
  this->DelFS(name);
  if (!result) return nullptr;
  return wxXmlResource::Get()->LoadPanel(parent, wxString::FromUTF8(xrcName));
}

    流程：把插件的 XRC 文本临时放进 acmemory: 虚拟文件系统 → wxXmlResource 加载 → 取面板 → 删临时文件。这实现了"插件用 XRC 声明界面、宿主负责实例化"的约定。

    AddWidget / WatchWindow——插件把组件挂到宿主窗口指定位置；宿主支持按 position 监听窗口创建并回调：

    bool PluginsManagerImpl::AddWidget(const wxString &position, wxWindow *widget) {
  if (auto itr = watchers_.find(position);
      itr != watchers_.end() && false == itr->second(widget)) {
    return true;   // 被监听者处理且返回 false → 不存储
  }
  if (auto itr = std::ranges::find_if(widgets_, [&position](const WidgetsNode &node) {
        return node.position == position;
      }); itr != widgets_.end()) {
    return false;  // 相同 position 已存在 → 拒绝
  }
  widgets_.emplace_back(WidgetsNode{widget, position});
  return true;
}

    本章要点¶

    • 加载分三阶段：包校验（CheckPackage）→ 解压装载（LoadPlugins）→ 实例化启动（CreateInstances），由生命周期事件驱动；
    • 包校验失败仅跳过，不影响整体启动；API 版本 ==1 是加载硬门槛；
    • 静态插件（编译期 PLUGINS_LIST_SIZE + 运行期 AddStaticPlugins）与动态插件统一进入 libraries_；
    • 实例通过 shared_ptr + 自定义删除器（Destroy/delete this）托管；
    • 生命周期事件 InitByApp → InitByGUI → FinishedByGUI → ExitByGUI → ExitByApp 全程要求主线程，退出时逆序 Stop。

    代码定位¶

    • 入口/退出：plugins_manager/plugins_manager.hxx（SetupPM/ShutdownPM）

    • 事件类型：plugins_manager/plugins_manager.hxx（EventType）
    • 库加载抽象：plugins_manager/detail/LibraryBase.cpp
