    07 · 序列化机制：类型分类与 pack/unpack 协议¶

    通信协议能不能高效、安全、类型安全地跑起来，取决于底层序列化。本章深入 plugins_base/plugins_stream.hxx 与 pack.hxx，把参数/返回值"打包→传输→解包"的类型体系讲透。

    7.1 类型分类：编译期判定¶

    序列化器的第一步，是给 C++ 参数类型分类。plugins_stream.hxx 定义了四个类型谓词：

    // trivial：算术类型，或"标准布局 + 平凡"的类
template <typename T>
constexpr bool is_trivial_v =
    std::is_arithmetic_v<T> ||
    (std::is_class_v<T> && std::is_standard_layout_v<T> && std::is_trivial_v<T>);

// 精确的 std::string
template <typename T>
constexpr bool is_std_string_v<T> = std::is_same_v<std::decay_t<T>, std::string>;

// C 字符串（char* / const char*）
template <typename T>
constexpr bool is_c_string_v<T> =
    std::is_pointer_v<T> && (std::is_same_v<std::decay_t<T>, char*> ||
                             std::is_same_v<std::decay_t<T>, const char*>);

// 通用指针（非 C 字符串）
template <typename T>
constexpr bool is_pointer_v<T> = std::is_pointer_v<T> && !is_c_string_v<T>;
    分类 判定 序列化策略
    trivial 算术 / 标准布局平凡类 按 sizeof 原样读写字节
    std::string 精确匹配 uint16_t 长度 + 字节
    C 字符串 char*/const char* 同上，读时 malloc，写时 strlen
    通用指针 其它指针 仅拷贝指针值（地址），不深拷贝
    wxString 特判 先转 utf8_string() 再当字符串
    JSON 兼容类型（pack.hxx） iguana 反射/容器 先转 JSON 字符串再按字符串传

    7.2 流上的读写原语¶

    IStream::Read / OStream::Write 针对不同分类提供模板重载，共同组成"每个类型都有确定编码"的协议。

    trivial 类型——按字节拷贝：

    template <typename T>
std::enable_if_t<is_trivial_v<T> && !std::is_const_v<T>, bool> Read(T &data) {
  return sizeof(T) == Read(&data, sizeof(T));
}
template <typename T>
std::enable_if_t<is_trivial_v<T>, bool> Write(const T &data) {
  return sizeof(T) == Write(&data, sizeof(T));
}

    字符串类型——长度前置（uint16_t）+ 数据：

    bool Write(const std::string &data) {
  assert(data.size() <= std::numeric_limits<uint16_t>::max()); // 硬上限 65535
  uint16_t length = static_cast<uint16_t>(data.size());
  return Write(length) && Write(data.data(), length);
}
bool Read(std::string &data) {
  uint16_t length = 0;
  if (!Read(length)) return false;
  data.resize(length);
  return Read(data.data(), data.size()) == length;
}

    wxString 的读写都走 utf8_string() 中间态，保证跨编码一致：

    bool Read(wxString &data) { std::string b; if (Read(b)) { data = wxString::FromUTF8(b); } }
bool Write(const wxString &data) { return Write(data.utf8_string()); }

    C 字符串——读时分配，写时计数：

    // 读：malloc 一段并置 null 结尾（调用方必须释放，pack_free 负责）
template <typename T> enable_if_t<is_c_string_v<T>, bool> Read(T &data) {
  uint16_t length; if (!Read(length)) return false;
  if (length == 0) { data = nullptr; return true; }
  auto buffer = (char *)malloc(length + 1);
  data = buffer; memset(buffer, 0, length + 1);
  return Read(buffer, length) == length;
}
// 写：nullptr 写 0；否则写 strlen
template <typename _Ty> enable_if_t<is_c_string_v<_Ty>, bool> Write(_Ty data) {
  uint16_t length = data ? static_cast<uint16_t>(strlen(data)) : 0;
  Write(length);
  return length > 0 ? Write(data, length) : true;
}

    通用指针——只传地址值，不深拷贝：

    // 读
template <typename _Ty> enable_if_t<is_pointer_v<_Ty>, bool> Read(_Ty &data) {
  intptr_t ptr = 0; if (!Read(ptr)) return false;
  data = reinterpret_cast<_Ty>(ptr); return true;
}
// 写
template <typename _Ty> enable_if_t<is_pointer_v<_Ty>, bool> Write(_Ty data) {
  return Write(reinterpret_cast<intptr_t>(data));
}

    这是文档明确点名的设计取舍：指针只复制指针值，避免深度拷贝。适用于大对象、跨插件传引用/共享数据的场景，但要求被指对象的生命周期覆盖整个调用过程（文档"性能建议"专门强调）。

    7.3 高层封装：pack.hxx¶

    pack.hxx 在流原语之上提供"参数包"级别的高层接口，给 funcation.hxx 使用（文档注明"其他地方使用要慎重"）。

    JSON 兼容类型判定（基于 iguana）：

    template <typename _Ty>
constexpr bool is_json_type_v =
    iguana::is_sequence_container<_Ty>::value ||   // 顺序容器（vector 等）
    iguana::is_associat_container<_Ty>::value ||   // 关联容器（map 等）
    iguana::is_reflection_v<_Ty>;                  // 有 REFLECTION 的结构体

    按类型估算字节数（get_type_size）：

    if constexpr (is_json_type_v<value_t>) {
    // 先 to_json 成字符串再递归估算
    iguana::string_stream ss; iguana::json::to_json(ss, v);
    return get_type_size(ss.str());
} else if constexpr (std::is_same_v<value_t, wxString>) {
    return get_type_size(v.utf8_string());
} else if constexpr (std::is_same_v<value_t, std::string>) {
    return v.length() + sizeof(uint16_t);      // 长度前缀
} else if constexpr (is_c_string_v<value_t>) {
    return strlen(v) + sizeof(uint16_t);
} else if constexpr (std::is_arithmetic_v<value_t> || is_pointer_v<value_t> ||
                     std::is_pod_v<value_t>) {
    return sizeof(value_t);
} else {
    static_assert(sizeof(value_t) == 0, "unsupported type"); // 编译期拒绝
}

    读写一字节不差——read_value/write_value 按同一套分类对称编码：

    template <typename _Ty> inline bool read_value(IStream *stream, _Ty &v) {
  if constexpr (is_json_type_v<std::decay_t<_Ty>>) {
    std::string json;
    if (!stream->Read(json)) return false;
    return utility::json::load_from_json(v, json.data(), json.size()); // JSON 反序列化
  } else {
    return stream->Read(v);
  }
}
template <typename _Ty> inline bool write_value(OStream *stream, const _Ty &v) {
  if constexpr (is_json_type_v<std::decay_t<_Ty>>) {
    iguana::string_stream ss; iguana::json::to_json(ss, v);
    return stream->Write(ss.str());
  } else {
    return stream->Write(v);
  }
}

    打包 / 解包（折叠表达式串联校验）：

    template <typename... Args> size_t get_bytes(Args &&...args) {
  return (get_type_size<Args>(std::forward<Args>(args)) + ...);
}
template <typename... Args> bool unpack_args(std::tuple<Args...> &args, IStream *stream) {
  return std::apply([stream](Args &...t) { return (read_value(stream, t) && ...); }, args);
}
template <typename... Args> void pack_result(OStream *stream, Args &&...args) {
  auto bytes = get_bytes(std::forward<Args>(args)...);
  stream->Resize(bytes);                       // 先按估算尺寸开缓冲区
  auto result = (write_value(stream, std::forward<Args>(args)) && ...);
  assert(result);
}

    pack_result 有个实用技巧：先用 get_bytes 精确估算出总大小，Resize 一次性开出缓冲区，避免流多次扩容。

    C 字符串清理（pack_free）——用 tuple_for_each 遍历参数元组，释放其中 C 字符串参数的堆内存：

    template <typename Tuple> inline void pack_free(Tuple &&tuple) {
  tuple_for_each(tuple, [](auto &&elem) {
    using value_t = std::decay_t<decltype(elem)>;
    if constexpr (is_c_string_v<value_t>) free(const_cast<char *>(elem));
  });
}

    7.4 协议的限制与边界¶

    限制 出处 说明
    字符串最长 65535 uint16_t 长度前缀 超长会触发 assert，属硬限制
    指针不深拷贝 is_pointer_v 分支 只传地址，生命周期须由调用方保证
    C 字符串需手动释放 Read 用 malloc 由 pack_free 在调用后统一释放
    JSON 类型需 iguana 反射 is_json_type_v 结构体要能 REFLECTION，容器需 iguana 可识别
    不支持任意类类型 static_assert 除上述分类外的类型在编译期直接拒绝

    7.5 设计解读与性能建议¶

    • 类型安全在编译期：function_traits + if constexpr 让"传错类型"在编译期报错，运行时几乎零开销；
    • 对称编码：read_value/write_value、get_type_size 对同一分类使用完全一致的格式，保证"估多少字节、就写多少、就读多少"；
    • 按需选型（文档建议）：
    • 小数据（int/float 等）→ 直接传值；
    • 大结构体 → 指针传递（只拷贝地址）；
    • 动态数据 → 保证生命周期覆盖调用过程。

    一句话总结这套协议：trivial 按位拷贝、字符串长度前缀、指针传地址、JSON 类型先转字符串——四类编码规则覆盖了插件间函数调用的绝大多数数据类型，且把"深拷贝成本"和"类型安全"都控制在合理边界内。

    本章要点¶

    • 类型分四类编码：trivial（按字节）、字符串（长度前缀）、C 字符串（malloc/free）、通用指针（只传地址），另有 wxString 与 JSON 兼容类型特判；
    • 字符串上限 65535、指针不深拷贝、C 字符串需 pack_free 释放；
    • get_bytes 先估尺寸再 Resize，避免流多次扩容；
    • 不支持的类类型在编译期 static_assert 拒绝；
    • 编码规则严格对称，保证"估算字节 = 写入字节 = 读取字节"。

    代码定位¶

    • 类型谓词与流：plugins_base/plugins_stream.hxx
    • 高层打包/解包：plugins_base/pack.hxx
    • 元组遍历：plugins_base/tuple_foreach.hxx
    • 函数签名解析：plugins_base/function_traits.hxx
