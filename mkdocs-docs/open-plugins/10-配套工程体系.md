# 10 · 配套工程体系：事件、i18n、日志、XRC、CMake 与测试

前九章围绕"插件核心"展开，而一个可用的插件框架还离不开一批横切能力：事件系统、国际化、日志、内存文件系统 + XRC、构建宏体系、测试与基准。本章把它们串起来，作为系列收尾。

## 10.1 事件系统：wxPluginEvent

插件之间除了"函数调用"（路由），还有"事件广播"通道。核心是 `plugins_sdk/event/plugin_event.hxx` 的 `wxPluginEvent`——它是 `wxNotifyEvent` 的子类，天然继承 wxWidgets 的事件派发能力：

```cpp
class wxPluginEvent : public wxNotifyEvent {
public:
  wxString GetValue(const wxString &key) const;       // 键值对读
  void SetValue(const wxString &key, const wxString &value); // 键值对写
  void SetSharedData(void *data, void *ctx, void (*dtor)(void *, void *)); // 共享数据
  void *GetSharedData(void) const;
  bool IsSuccess(void) const;  void SetSuccess(bool success);  // 状态
  int32_t GetCode(void) const; void SetCode(int32_t code);     // 错误码
private:
  wxPluginEventPrivate *m_private;
  wxDECLARE_DYNAMIC_CLASS_NO_ASSIGN(wxPluginEvent);
};
```

**两种数据传递方式**（对应 `docs/mechanism.md`）：

| 方式 | 接口 | 适用 |
| ---- | ---- | ---- |
| **键值对** | `SetValue/GetValue(key, wxString)` | 简单字段 |
| **SharedData** | `SetSharedData(ptr, ctx, dtor)` + `GetSharedData()` | 大数据、零拷贝 |

SharedData 的设计很讲究——**事件不拥有数据，只持有指针引用，配合自定义析构函数管理生命周期**：

```cpp
MyData *data = new MyData{...};
event.SetSharedData(data, nullptr, [](void *data, void *ctx) {
  delete static_cast<MyData *>(data);      // 事件析构时自动释放
});
// 接收方
MyData *received = static_cast<MyData *>(event.GetSharedData());
```

配套宏支持静态事件表：

```cpp
#define wxPluginEventHandler(func) \
  wxEVENT_HANDLER_CAST(::Anycubic::Plugins::SDK::wxPluginEventFunction, func)
#define EVT_PLUGIN_EVT(evt, id, fn) wx__DECLARE_EVT1(evt, id, wxPluginEventHandler(fn))
```

## 10.2 国际化：i18n

i18n 贯穿"源码标记 → 提取 → 翻译 → 编译 → 运行时加载 → 嵌入二进制"全链路，风格与 Slic3r/OrcaSlicer 一脉相承（`plugins_base/i18n.hxx` 注释明确"copy from Slic3r::GUI::I18N::translate"）。

**翻译宏**（开发与发布双模式）：

```cpp
#define _(s)     Anycubic::Plugins::I18n::translate((s))          // wxString
#define _L(s)    Anycubic::Plugins::I18n::translate((s))
#define _utf8(s) Anycubic::Plugins::I18n::translate_utf8((s))     // std::string
#define _CTX(s, ctx)    Anycubic::Plugins::I18n::translate((s), (ctx)) // 带上下文
#define _CTX_utf8(s, ctx) Anycubic::Plugins::I18n::translate_utf8((s), (ctx))
#define _devL(s) wxString((s))     // 开发阶段不翻译
#define _omitL(s) ("")             // 忽略翻译
#define L(s) s                     // 仅标记可本地化字符串（xgettext 提取用）
```

`_CTX` 用于解决一词多义（同词不同语境）：

```cpp
wxString saveFile = _CTX("Save", "File operation");
wxString saveGame = _CTX("Save", "Game operation");
```

`I18n::translate` 内部统一走 `wxGetTranslation`，支持 char*/wchar_t*/std::string/std::wstring/wxString 多种重载及复数形式。

**构建链路**（`cmake/generate.cmake` 的三个函数）：

| 函数 | 作用 |
| ---- | ---- |
| `i18n_generate_pot(target, pot, destdir, langs...)` | 用 `xgettext` 扫描源码生成 POT；为每种语言生成/合并 PO |
| `i18n_generate_mo(search_dir)` | 用 `msgfmt` 把 PO 编译成 MO 二进制 |
| `i18n_generate_embed(target, search_dir)` | 把 MO 转成 C 数组（`0x..`）嵌入可执行文件 |

`i18n_generate_pot` 的关键调用（`generate.cmake`）：

```cmake
execute_process(COMMAND ${GETTEXT_XGETTEXT_EXECUTABLE}
  --package-name=${target_name} --from-code=UTF-8
  --keyword=L --keyword=_ --keyword=_L --keyword=_u8L
  --keyword=L_CONTEXT:1,2c --keyword=_L_PLURAL:1,2
  --add-comments=TRN -n --debug --boost -f ${listfile} -o ${pot} ...)
```

`i18n_generate_embed` 把 `.mo` 文件读成 HEX 数组、连同 MD5 一起生成 `PACKAGE_DATA[]`，插件初始化时通过 `acTranslationsLoader` 从内存加载：

```cpp
acTranslationsLoader loader;
loader.LoadFromMemory(mo_data, mo_size, mo_md5);   // 或 LoadFromFile(...)
```

运行时，manager 在 `kEventInitByGUI` 时 `wxTranslations::Get()->SetLoader(translations_loader_)` 接入 wxWidgets 翻译体系。

## 10.3 日志系统：easy_log

`easy_log` 基于 spdlog，封装成带模块名的分级日志。初始化与使用：

```cpp
anycubic::logger::setup_log(log_path, level, enable_console); // 全局配置
anycubic::logger::register_logger(mname);                     // 注册一个模块日志
```

日志 API（`log.hxx`）：

```cpp
bool setup_log(const char *path, level_enum default_level, bool enable_console = false);
bool register_logger(const char *mname, bool compression = true);
bool unregister_logger(const char *mname);
bool set_level(const char *mname, level_enum level);
bool set_pattern(const char *mname, const char *pattern = DEFAULT_PATTERN);
bool should_log(const char *mname, level_enum level);
bool log_(const char *mname, const source_loc &loc, level_enum level, const char *msg);
```

**模块宏体系**——只要目标定义了 `MODULE_NAME`（CMake 里 `target_compile_definitions MODULE_NAME="xxx"`），就能直接用无参模块宏：

```cpp
#define LOG_TRACE(...)   LOG_TRACE_(MODULE_NAME, __VA_ARGS__)
#define LOG_DEBUG(...)   LOG_DEBUG_(MODULE_NAME, __VA_ARGS__)
#define LOG_INFO(...)    LOG_INFO_(MODULE_NAME, __VA_ARGS__)
#define LOG_WARN(...)    LOG_WARN_(MODULE_NAME, __VA_ARGS__)
#define LOG_ERROR(...)   LOG_ERROR_(MODULE_NAME, __VA_ARGS__)
#define LOG_CRITICAL(...) LOG_CRITICAL_(MODULE_NAME, __VA_ARGS__)
// 条件版 LOG_*_IF、管理宏 REGISTER_LOGGER/SET_LEVEL/SET_PATTERN/SET_OUTPUT
```

`log_.cpp` 的实现要点（sink 装配）：

- `register_logger` 用 `dist_sink_mt` 组合多个 sink：可选 console（`stdout_color_sink_mt`）+ 必选按日滚动文件（`daily_file_sink`，文件名 `basename.YYYYMMDD` 冲突自动追加计数）；
- 开启 debug 级别时还会挂 `udp_sink`（可配 `AC_LOG_HOST`，默认 `127.0.0.1:55535`），支持把日志发到调试服务；
- 每个日志调用先 `should_log` 过滤（避免格式化开销），再带 `source_loc{__FILE__,__LINE__,__func__}` 写入。

`easy_log/stackstrace.hxx` 提供 `FUNC_ENTRY`/`FUNC_LEAVE` 等**函数进出栈跟踪宏**（配合 `ENABLE_STRACE`），这也是前几章代码里大量 `FUNC_ENTRY/LEAVE` 的来源。

## 10.4 内存文件系统与 XRC

插件界面用 **XRC（XML 资源）** 声明。为了让插件把 XRC 字符串"动态喂给"宿主，manager 自建了一个内存文件系统 `MemoryFSHandler`（`detail/fshandler.*`）：

```cpp
class MemoryFSHandler : public wxFileSystemHandler {
  bool AddFile(const wxString &filename, const void *data, size_t size);
  bool RemoveFile(const wxString &filename);
};
```

配合 `wxXmlResource`，插件可以：
1. 用 `host->AddFS(name, xrc字符串)` 把 XRC 写进 `acmemory:` 虚拟路径；
2. `wxXmlResource::Get()->Load("acmemory:" + name)` 实例化；
3. `DelFS` 清理。

`detail/xrc/xh_webview.*` 还实现了 **wxWebView 的 XRC 处理器**（`WebviewHandler`），使 XRC 里能直接声明 WebView 组件——这是"界面即配置、资源动态注入"的关键一环（第 4 章 `CreatePanel` 已演示）。

## 10.5 构建宏体系：CMake

仓库把跨平台构建封装成一套 CMake 宏（`cmake/`），核心可复用件：

| 宏/函数 | 文件 | 作用 |
| ---- | ---- | ---- |
| `add_shared / add_static` | `basic.cmake` | 建共享/静态库 + 生成导出头（`generate_export_header`） |
| `add_shared_plugin / add_static_plugin` | `basic.cmake` | 建插件目标，注入 `MODULE_NAME`/`prefix`/`ENABLE_STRACE`，输出名 `plugin_<name>`，分组到 "Plugins_*" |
| `add_subdirs / add_subdirsDemos` | `subdir.cmake` | 按目录存在性批量 add_subdirectory |
| `add_subdirTEST / add_subdirGTEST / add_subdirBench` | `subdir.cmake` | 测试/基准的独立开关与目标生成（按 `*_Test.cpp`/`*_Bench.cpp` 一个文件一个可执行） |
| `add_rc_shared` | `generate.cmake` | 资源库（隐藏可见性 + 导出头） |
| `generate_source_file` | `generate.cmake` | 把任意文件读成 HEX 数组生成 `.cpp`（资源/翻译嵌入的底座） |
| `i18n_generate_pot/mo/embed` | `generate.cmake` | i18n 构建链路 |
| `generate_build_header` | `build.cmake` | 生成 `build_info.h`（`GIT_COMMIT_HAST/GIT_BRANCHE/BUILD_TIME`，Debug 下注入 MSVC 内存泄漏检测宏） |
| `setTartetBasic / SetInstall / module_install` | `basic.cmake` | 目标依赖解析、头文件安装 |

```cmake
# basic.cmake：共享库统一可见性（macOS/Linux 隐藏符号）
set_target_properties(${sub_project_name} PROPERTIES
    CXX_VISIBILITY_PRESET hidden
    C_VISIBILITY_PRESET hidden
    VISIBILITY_INLINES_HIDDEN ON)
target_compile_options(${sub_project_name} PRIVATE
    -fvisibility=hidden -fvisibility-inlines-hidden -Wl,--exclude-libs,ALL)
```

`generate_build_header` 的一个细节：Debug + Windows 下自动开启 MSVC 内存泄漏检测：

```cmake
file(APPEND ${filename}
  "#if defined(__WXMSW__) && !defined(NDEBUG)\n"
  "#include <crtdbg.h>\n"
  "#define new new(_NORMAL_BLOCK, __FILE__, __LINE__)\n"
  "#endif\n")
```

## 10.6 测试、基准与示例插件

| 目录 | 内容 |
| ---- | ---- |
| `Test/` | 单元测试，`ENABLE_TEST`/`ENABLE_GTEST` 开关；`*_Test.cpp` 按文件名一个可执行；覆盖插件管理器、流、AES、WebView、事件 |
| `Bench/` | 基准测试，`ENABLE_BENCH` + `find_package(benchmark)`，`*_Bench.cpp` |
| `plugins/` | 示例/测试插件（`app`、`tabbook`、`utility`、`luatest`），`plugins/README.md` 说明：**默认不编译，开启 ENABLE_TEST 与 ENABLE_GTEST 才编译，实现均为空接口** |
| `instrument/` | 崩溃栈符号化（msw/unix 分平台），供诊断工具用 |

`plugins/CMakeLists.txt` 的装配逻辑（静态插件如何被收进 `PM_DEPS`）：

```cmake
if (ENABLE_TEST AND ENABLE_GTEST)
  file(GLOB_RECURSE SUB_PLUGIN "*.cmake")   # 收集 plugins/**/*.cmake
  foreach(plugin ${SUB_PLUGIN})
    include(${plugin})                      # 每个 .cmake 调 add_shared_plugin/add_static_plugin
  endforeach()
  set(PM_DEPS "${PM_DEPS}" PARENT_SCOPE)
endif()
```

每个插件一个 `.cmake`（如 `app.cmake`）：

```cmake
file(GLOB_RECURSE SRC_G "${CMAKE_CURRENT_LIST_DIR}/*.h*" "${CMAKE_CURRENT_LIST_DIR}/*.c" "${CMAKE_CURRENT_LIST_DIR}/*.cpp")
add_static_plugin(app ${SRC_G})
```

`luatest` 示例还展示了**插件内嵌 Lua 脚本解析**（`detail/lua_parser.cpp` + `lua_plugin.lua`，用 `tree-sitter`），说明插件可以是"脚本驱动"的——这进一步印证了插件体系的可扩展性。

## 10.7 横切能力的协作关系（收尾）

把整套支撑体系与插件核心拼在一起，OpenPlugins 的完整能力面是：

| 能力 | 载体 | 与插件核心的关系 |
| ---- | ---- | ---- |
| 插件通信 | `EventRouter` + `IStream/OStream` | 插件间函数调用的主通道 |
| 事件广播 | `wxPluginEvent`（SDK） | 插件/宿主事件派发、共享数据 |
| Web 能力 | `WebView/` + `WebviewApiHandler` | 插件以 Web API 暴露业务 |
| 国际化 | `i18n.hxx` + gettext 构建链路 | 插件与宿主语言统一 |
| 日志 | `easy_log`（spdlog） | 全链路可观测 |
| 界面/资源 | `MemoryFSHandler` + XRC + `xh_webview` | 插件动态注入界面 |
| 配置 | `PMConfig` + 加密配置 | 插件读写持久化配置 |
| 构建 | CMake 宏体系 | 一库多用、跨平台 |
| 质量 | `Test/`、`Bench/`、`instrument/` | 正确性、性能、诊断 |

## 本章要点

- 事件系统 `wxPluginEvent` 支持键值对与 SharedData（指针 + 自定义析构）两种数据传递，并带状态/错误码；
- i18n 全链路：`xgettext` 提 POT → `msgfmt` 编 MO → HEX 数组嵌入，运行时经 `acTranslationsLoader` 加载；`_CTX` 解决一词多义；
- 日志基于 spdlog：模块宏 + 按日滚动 + UDP 调试输出 + 栈跟踪宏（`FUNC_ENTRY/LEAVE`）；
- 内存文件系统 + XRC + `xh_webview` 支撑"插件用 XML 声明界面、宿主动态实例化"；
- CMake 宏体系统一构建：共享/静态库、插件目标、i18n、构建信息、测试/基准开关；
- 示例插件默认不编译，仅在开启测试时参与构建。
