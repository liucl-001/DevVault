# 03 · 插件契约：接口、元数据与 C ABI

插件化框架的立身之本，是"**插件长什么样、宿主怎么调用它**"这份契约。本章拆解 `plugins_base` 里的完整契约：元数据结构、纯虚接口、以及跨动态库边界的 C ABI 导出。

## 3.1 插件元数据：PluginInfo

插件在被加载前，宿主需要一份"说明书"来判断它是什么、依赖谁、版本多少。这就是 `PluginInfo`（`plugins_base/plugins_base.hxx`）：

```cpp
struct PluginInfo {
  int16_t plugin_api;       ///< 插件 api 版本
  int16_t plugin_type;      ///< 插件类型: 1: core; 2: dlg_widgets; 4: sdk; 8: webview_widgets
  int32_t dependency_count; ///< 插件依赖数量
  const char **dependency;  ///< 插件依赖（插件名数组）
  const char *name;         ///< 插件名称
  const char *description;  ///< 插件描述
  int64_t version;          ///< 插件版本
};
```

字段语义：

| 字段 | 说明 |
| ---- | ---- |
| `plugin_api` | 插件遵循的 API 版本。管理器硬性校验 `==1` 才加载 |
| `plugin_type` | 位掩码风格：`1=core`、`2=dlg_widgets`、`4=sdk`、`8=webview_widgets` |
| `dependency` | 依赖的其他插件名数组，必须静态存储 |
| `version` | 插件版本，`int64_t` |

创建插件的标准填法（`docs/create_plugin.md` 的 address 示例）：

```cpp
extern "C" {
PLUGIN_EXPORT_GETINFO(address_API, PLUGIN_NAME) {
  static const char *depends[] = {"utility"}; // 依赖的插件列表，注意一定要静态变量
  static PluginInfo info{
      .plugin_api = 1,
      .plugin_type = 0xe,   // core(1) | sdk(4) | webview_widgets(8)
      .dependency_count = sizeof(depends) / sizeof(depends[0]),
      .dependency = depends,
      .name = PLUGIN_NAME_STR,
      .description = PLUGIN_NAME_STR,
      .version = 1,
  };
  return &info;
}
PLUGIN_EXPORT_SETUP(address_API, PLUGIN_NAME) {
  return new Anycubic::Plugins::AddressPlugin(host);
}
}
```

注意两处"必须"：

- `depends` 与 `info` 都必须是**函数内静态变量**——因为返回的是裸指针，宿主会长期持有，局部变量会悬垂；
- `plugin_type = 0xe` 即 `core | sdk | webview_widgets` 的位组合（`1|4|8`），说明该插件同时具备多类能力标记。

## 3.2 插件实体接口：Plugin

宿主拿到 `PluginInfo` 之后，通过 `_setup` 拿到真正的插件对象，其类型是纯虚接口 `Plugin`（`plugins_base/plugins.hxx`）：

```cpp
struct Plugin {
  virtual ~Plugin() = default;
  virtual const char *Name(void) = 0;               // 插件名称
  virtual bool Start(void) = 0;                     // 启动
  virtual void Stop(void) = 0;                      // 停止
  virtual bool AttachEvt(wxEvtHandler *evt) = 0;    // 附加事件处理器
  virtual bool DetachEvt(wxEvtHandler *evt) = 0;    // 分离事件处理器
  virtual bool BindEvt(wxPanel *panel, wxWindow *parent = nullptr,
                       wxString *bmp = nullptr) = 0;       // 绑定事件/面板
  virtual bool CreateWebview(wxWebView *view, wxWindow *parent = nullptr,
                             wxString *bmp = nullptr) = 0; // 创建 WebView
  virtual void Destroy(void) = 0;                   // 销毁
};
```

生命周期语义很清晰：

- `Start/Stop`：插件的业务启停（manager 在实例化完成后调用 `Start`，退出时逆序调 `Stop`）；
- `AttachEvt/DetachEvt/BindEvt`：让插件把自己的界面/事件挂到主程序给的容器上；
- `CreateWebview`：让插件把内容渲染进主程序提供的 `wxWebView`；
- `Destroy`：插件负责 `delete this`（self-destroy 模式）。

### 3.2.1 PluginBase：免界面的默认实现

很多插件根本不需要界面，于是提供 `PluginBase` 作为便捷基类，把界面相关方法全部默认返回 `true`：

```cpp
struct PluginBase : public Plugin {
  virtual bool AttachEvt(wxEvtHandler *) { return true; }
  virtual bool DetachEvt(wxEvtHandler *) { return true; }
  virtual bool BindEvt(wxPanel *, wxWindow *, wxString *) { return true; }
  virtual bool BindEvt(wxWebView *, wxWindow *, wxString *) { return true; }
  virtual bool CreateWebview(wxWebView *, wxWindow *, wxString *) { return true; }
};
```

文档明确建议：**根据插件自身需求选择 `PluginBase` 或 `Plugin`**。只注册函数、不做界面的插件继承 `PluginBase` 即可。

## 3.3 宿主接口：PluginHost

宿主（管理器）向插件提供的全部能力，收敛在 `PluginHost` 纯虚接口里。插件在构造函数里拿到 `PluginHost*`，之后就靠它干活：

```cpp
struct PluginHost {
  virtual PluginRouter *Router(void) = 0;                    // 取路由，注册/调用函数
  virtual bool HasPlugin(const char *name) = 0;              // 某插件是否存在
  virtual Plugin *GetPlugin(const char *name) = 0;           // 取某插件实例
  virtual wxWindow *GetWindow(const char *postion) = 0;      // 按位置取宿主窗口
  virtual bool WatchWindow(const char *postion, void *context,
      bool (*callback)(void*, wxWindow*)) = 0;               // 监听窗口创建
  virtual wxPanel *CreatePanel(const wxString& position,
      const wxString& xrcName, const wxString& xrc) = 0;     // 按位置建面板
  virtual wxPanel *CreatePanel(wxWindow *parent, ...) = 0;   // 按父窗建面板
  virtual wxString Language(void) = 0;                       // 当前语言
  virtual bool LoadTranslationFromData(...) = 0;             // 从内存加载翻译
  virtual bool LoadTranslationFromFile(...) = 0;             // 从文件加载翻译
  virtual bool AddFS(const wxString&, const wxString&) = 0;  // 内存虚拟文件系统
  virtual bool DelFS(const wxString&) = 0;
  virtual bool AddFS(const wxString&, void*, size_t) = 0;
  virtual bool GetValue(const wxString&, wxString&) = 0;     // 配置读
  virtual bool SetValue(const wxString&, const wxString&, bool) = 0;
  virtual bool GetEncryptValue(...) = 0;                     // 加密配置读
  virtual bool SetEncryptValue(...) = 0;
  virtual void Free(const char *value) = 0;                  // 释放配置字符串
};
```

分组理解：

| 能力域 | 方法 |
| ---- | ---- |
| 路由与插件互查 | `Router` / `HasPlugin` / `GetPlugin` |
| 窗口与面板 | `GetWindow` / `WatchWindow` / `CreatePanel`（两种重载） |
| 国际化 | `Language` / `LoadTranslationFromData/File` |
| 虚拟文件系统（XRC） | `AddFS` / `DelFS` |
| 配置（含加密） | `Get/SetValue`、`Get/SetEncryptValue`、`Free` |

一个细节：`Get/SetValue` 与 `Get/SetEncryptValue` 成对出现，说明插件配置支持"敏感项加密存储"，加密能力来自 `utility/encrypt`（AES/RSA），`PMConfig` 接口在 manager 侧定义并注入。

## 3.4 路由接口：PluginRouter 与 RequestHandler

插件注册函数、宿主分发调用，都通过路由。核心是两个接口：

```cpp
struct RequestHandler {                 // 单个函数的执行载体
  virtual void Execute(IStream *data, OStream *result) = 0;
  virtual void Destroy() = 0;
};

struct PluginRouter {                   // 路由表
  virtual bool AddFunction(const char *fname, RequestHandler *handler) = 0;
  virtual bool ExecuteFunction(const char *plugin, const char *fname,
                               IStream *data, OStream *result) = 0;
};
```

- 插件侧通过 `REGISTER_FUNCATION(type, func)` 把成员函数包装成 `RequestHandler` 注册；
- 宿主侧通过 `dispatch_call<ret>(host, plugin, fname, args...)` 或 `router->ExecuteFunction` 调用；
- 参数与返回值都走 `IStream`/`OStream` 内存流（第 6、7 章详述）。

## 3.5 C ABI 导出：让动态库边界可见

动态插件是独立的共享库（`plugin_*.dll/.so/.dylib`），宿主用 `wxDynamicLibrary` 按符号名取函数指针。为了保证跨编译器、跨平台的 C++ ABI 稳定，导出必须用 `extern "C"`：

```cpp
constexpr int PLUGIN_API_VERSION = 1;

#define PLUGIN_EXPORT_GETINFO(export, plugin_name) \
  export PluginInfo *BOOST_PP_CAT(plugin_name, _getInfo)()
#define PLUGIN_EXPORT_SETUP(export, plugin_name) \
  export struct Anycubic::Plugins::Plugin *BOOST_PP_CAT(plugin_name, _setup)( \
      struct Anycubic::Plugins::PluginHost *host)
```

- `BOOST_PP_CAT` 把插件名拼进符号：`<plugin>_getInfo` / `<plugin>_setup`；
- 宿主通过 `GetProcAddress` 取这两个符号（见 `LibraryBase.hxx` 的 `GetProcAddressAll`）；
- 名称匹配严格：动态插件输出名 `plugin_<name>`，运行期再按前缀 `plugin_` + 扩展名过滤识别（见第 8 章 `IsPlugins`）。

### 3.5.1 动态 vs 静态：LibraryBase 统一抽象

无论是动态库（`wxDynamicLibrary` 加载）还是静态插件（编译期注册），manager 都用同一套接口驱动：

```cpp
struct LibraryBase {
  virtual bool Loaded(void) const = 0;
  virtual bool LoadLibrary(const wxString &libName) = 0;
  virtual void UnloadLibrary() = 0;
  PluginInfo *GetPluginInfo() const;          // 调 getInfo_
  Plugin *SetupPlugin(PluginHost *host) const; // 调 setup_
protected:
  plugin_getInfo_t getInfo_;
  plugin_setup_t setup_;
};

struct LibraryShared : LibraryBase { /* 内部持有 wxDynamicLibrary m_library */ };
struct LibraryStatic : LibraryBase { /* Loaded() 恒为 true */ };
```

- `LibraryShared`：真实加载 `.dll/.so/.dylib`，`RawGetSymbol` 取导出符号；
- `LibraryStatic`：直接持有 `getInfo`/`setup` 函数指针（静态插件已在主程序二进制内），`Loaded()` 恒真。

这样，动态插件与静态插件在 manager 的 `libraries_` 列表里一视同仁，后续生命周期、依赖解析、路由都对它们统一处理。

## 3.6 一个最小插件的全貌

综合 `docs/create_plugin.md`，一个只注册函数的插件骨架：

```cpp
class AddressPlugin : public Plugin {
public:
  AddressPlugin(PluginHost *host) : host_(host) {
    auto router = host_->Router();
    router->REGISTER_FUNCATION(AddressPlugin, get_cloud_url); // 注册
  }
  const char *Name(void) override { return PLUGIN_NAME_STR; }
  bool Start(void) override { return true; }
  void Stop(void) override {}
  void Destroy(void) override { delete this; }
private:
  std::string get_cloud_url() const { return "https://xxx"; }
  PluginHost *host_;
};
```

配合 `extern "C"` 的 `_getInfo`/`_setup` 导出，这个插件就能被 manager 识别、实例化、注册函数并被其他插件调用——一份契约，两端遵守。

## 本章要点

- `PluginInfo` 是插件的"说明书"：API 版本、类型位掩码、依赖、名称、版本；依赖数组必须静态存储；
- `Plugin` 是插件实现的接口，`PluginBase` 提供免界面的默认实现；`Destroy` 由插件自行 `delete this`；
- `PluginHost` 是宿主给插件的全部能力：路由、窗口、面板、翻译、虚拟文件系统、配置（含加密）；
- 跨二进制边界靠 `extern "C"` 的 `_getInfo/_setup` 两个导出符号，动态/静态插件统一收敛为 `LibraryBase`。

## 代码定位

- 接口全集：`plugins_base/plugins.hxx`
- 元数据 + 导出宏：`plugins_base/plugins_base.hxx`
- 动态/静态库抽象：`plugins_manager/detail/LibraryBase.{hxx,cpp}`
- 插件骨架示例：`docs/create_plugin.md`、`plugins/utility/utility_plugin.cpp`
