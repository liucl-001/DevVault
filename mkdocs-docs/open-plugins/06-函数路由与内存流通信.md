# 06 · 函数路由与内存流通信：插件之间的调用主通道

插件要互相调用函数，靠的就是"**函数路由（EventRouter）+ 内存流（IStream/OStream）**"这套机制。本章把注册、调用、数据流三件事讲透。

## 6.1 全局路由表：EventRouter

管理器持有一个全局路由 `EventRouter`（`detail/router.{hpp,cpp}`），实现 `PluginRouter` 接口。路由表的 key 是**字符串拼接**：`"插件名/函数名"`。

```cpp
class EventRouter : public Anycubic::Plugins::PluginRouter {
public:
  void SetPluginName(const wxString &name);      // 注册前先设置当前插件名
  bool AddFunction(const char *fname, RequestHandler *handler) override;
  bool ExecuteFunction(const char *plugin, const char *fname,
                       IStream *data, OStream *result) override;
private:
  wxString KeyName(const wxString &plugin, const wxString &fname) const;
  wxString plugin_name_;
  std::map<wxString, std::shared_ptr<RequestHandler>> funcs_;
};
```

- `funcs_` 是 `std::map<wxString, shared_ptr<RequestHandler>>`，天然保证 key 唯一；
- key 由 `KeyName` 生成，格式 `wxString::Format("%s/%s", plugin, fname)`；
- `shared_ptr` + 自定义删除器 `global_destroy`（调用 `RequestHandler::Destroy`）统一管理处理器生命周期。

## 6.2 注册：REGISTER_FUNCATION 宏

插件构造函数里一行宏即可完成注册（`plugins_base/funcation.hxx`）：

```cpp
#define REGISTER_FUNCATION_SELF(type, func, self)                              \
  AddFunction(BOOST_PP_STRINGIZE(func), Anycubic::Plugins::make_call(          \
                                            &type::func, self))
#define REGISTER_FUNCATION(type, func) REGISTER_FUNCATION_SELF(type, func, this)
```

- `BOOST_PP_STRINGIZE(func)` 把函数名转字符串（路由 key 的一部分）；
- `make_call(&type::func, this)` 把成员函数转成 `RequestHandler`（见下）；
- `AddFunction` 是 `PluginRouter` 的方法（插件拿 `host_->Router()` 调用），内部 `SetPluginName` 已在 manager 初始化时设好当前插件名。

示例（`utility_plugin.cpp`）：

```cpp
router->REGISTER_FUNCATION(UtilityPlugin, pcid);
router->REGISTER_FUNCATION(UtilityPlugin, language);
router->REGISTER_FUNCATION(UtilityPlugin, get_temp_path);
...
```

## 6.3 包装：make_call 如何把成员函数变成处理器

`make_call` 是这套机制的灵魂——它利用 `function_traits`（第 7 章涉及）在**编译期**解析函数签名，生成一个 lambda 包装器：

```cpp
template <typename Function, typename Self>
RequestHandler *make_call(const Function &func, Self *self) {
  using func_traits = function_traits<Function>;
  auto h = [func, self](IStream *data, OStream *result) {
    using ret_type = std::decay_t<typename func_traits::return_type>;
    using arg_types = typename func_traits::bare_tuple_type;
    arg_types args;
    constexpr size_t arg_count = std::tuple_size_v<arg_types>;
    if constexpr (arg_count > 0) unpack_args(args, data);   // 从输入流解出参数
    if constexpr (std::is_void_v<ret_type>) {
      std::apply(func, std::tuple_cat(std::make_tuple(self), args)); // 调用（void）
    } else {
      ret_type ret = std::apply(func, std::tuple_cat(std::make_tuple(self), args));
      pack_result(result, ret);                              // 打包返回值到输出流
    }
    pack_free(args);                                         // 释放 C 字符串参数
  };
  return FuncationWrapper::Create(std::move(h));
}
```

机制要点：

| 步骤 | 说明 |
| ---- | ---- |
| 编译期解析 | `function_traits<Function>` 提取 `return_type` 与 `bare_tuple_type`（参数元组） |
| 参数解包 | `unpack_args(args, data)`：按签名从输入流逐字段反序列化 |
| 调用注入 this | `std::apply(func, std::tuple_cat(std::make_tuple(self), args))`：`this` 拼在参数最前 |
| 返回值打包 | 非 void 时 `pack_result(result, ret)` 序列化回输出流 |
| 资源清理 | `pack_free(args)` 释放 C 字符串参数的堆内存 |

`FuncationWrapper` 则是这个 lambda 的 RAII 外壳，实现 `RequestHandler` 的 `Execute/Destroy`。

## 6.4 调用：dispatch_call

调用侧由模板 `dispatch_call` 完成"参数打包 → 路由执行 → 返回值解包"三步：

```cpp
template <typename ret_type, typename router_type, typename... Args>
ret_type dispatch_call(router_type *router, const char *plugin,
                       const char *fname, Args &&...args) {
  std::vector<char> argsData;
  constexpr auto args_size = sizeof...(Args);
  if constexpr (args_size > 0) {
    auto bytes = get_bytes(args...);
    argsData.resize(bytes);
    OStream os(argsData.data(), bytes);
    pack_result(&os, std::forward<Args>(args)...);   // ① 参数序列化
  }
  IStream is(argsData.data(), argsData.size());
  OStream os;
  auto result = router->ExecuteFunction(plugin, fname, &is, &os); // ② 路由执行（同步）
  if (!result) return ret_type();
  if constexpr (!std::is_void_v<ret_type>) {
    IStream rs(os.Data(), os.Size());
    ret_type ret;
    unpack_args_read(&rs, ret);                     // ③ 返回值反序列化
    return ret;
  }
}
```

另有一个便捷重载直接吃 `PluginHost*`：

```cpp
ret_type dispatch_call(PluginHost *host, const char *plugin, const char *fname,
                       Args &&...args) {
  auto router = host->Router();
  return dispatch_call<ret_type>(router, plugin, fname, std::forward<Args>(args)...);
}
```

调用示例（`docs/mechanism.md`）：

```cpp
int result = dispatch_call<int>(router, "plugin", "calculate", 10, 20);
```

## 6.5 路由执行：同步 + 异常安全

`EventRouter::ExecuteFunction` 是同步阻塞调用，并做了异常兜底：

```cpp
bool EventRouter::ExecuteFunction(const char *plugin, const char *fname,
                                  IStream *data, OStream *result) {
  auto key = KeyName(plugin, fname);
  if (auto itr = funcs_.find(key); itr != funcs_.end()) {
    try {
      itr->second->Execute(data, result);        // 同步执行
    } catch (const std::exception &e) {
      return false;                              // 执行异常 → 返回失败
    }
    return true;
  }
  assert(false);                                 // 未注册函数
  return false;
}
```

- **同步语义**：`ExecuteFunction` 会阻塞到目标函数执行完成，返回值（经序列化）随 `OStream` 带回；
- **未注册/异常**：返回 `false`，调用方 `dispatch_call` 里 `assert(result)` 并返回默认构造的 `ret_type()`；
- `AddFunction` 对重复注册返回 `false`（key 已存在），防止同名函数被覆盖。

## 6.6 内存流：IStream / OStream 抽象

参数和返回值之所以能在"插件二进制之间"安全传递，是因为都塞进了统一的内存流。`IStream`（读）/ `OStream`（写）是对一块内存缓冲区的流式封装：

```cpp
struct IStream {      // 读
  IStream(const void *data, size_t size);
  size_t Read(void *data, size_t size);
  size_t Size(); size_t Tellg(); size_t Seekg(size_t pos);
  const void *Data();
  // 模板化读取：trivial / C 字符串 / std::string / wxString / 指针
  template<typename T> enable_if_t<is_trivial_v<T> && !is_const_v<T>, bool> Read(T &data);
  ...
};

struct OStream {      // 写
  OStream(void *buffer, size_t size);  // 也可自持有缓冲区
  size_t Write(const void *data, size_t size);
  size_t Size(); size_t Tellp(); size_t Seekp(size_t pos); size_t Resize(size_t size);
  void *Data();
  // 模板化写入：trivial / C 字符串 / std::string / wxString / 指针
  ...
};
```

内存流的两种构造形态很关键：

1. **外接缓冲区**：`IStream(ptr, size)` / `OStream(ptr, size)` —— 调用时把参数缓冲区、返回值缓冲区直接包成流；
2. **自持缓冲区**：`OStream(size = 0)` / `IStream(size)` —— 流内部 `new` 一块缓冲并成为 owner，`Resize` 可动态扩容。

> 这也解释了"统一通信协议"的本质：**它不依赖进程间 IPC，而是进程内的、基于内存块的、类型安全的函数调用协议**。插件之间通过共享同一地址空间 + 统一流格式完成同步调用。

## 6.7 一次调用的完整旅程

把注册与调用串起来，一次跨插件调用 `dispatch_call<int>(host, "utility", "language")` 的完整路径：

```
调用方插件
  dispatch_call<int>(host, "utility", "language")
    → host->Router() 取到 EventRouter
    → pack_result 把参数写进 OStream（此处无参数）
    → router->ExecuteFunction("utility", "language", is, os)
        → key = "utility/language" 查 funcs_
        → 命中 UtilityPlugin::language 的包装器
        → unpack_args 解参数（无）
        → std::apply(&UtilityPlugin::language, (this,)) 执行
        → pack_result(os, ret) 写回 "zh_CN"
    → dispatch_call 从 os 解出 ret 返回 "zh_CN"
 调用方得到返回值
```

## 本章要点

- 路由表 `EventRouter` 以 `"插件/函数"` 为 key，`std::map` + `shared_ptr` 管理；
- `REGISTER_FUNCATION` 一行宏完成"成员函数 → 处理器"注册，`make_call` 在编译期解析签名；
- `dispatch_call` 是调用侧模板：打包参数 → 路由执行 → 解包返回值，同步阻塞；
- `IStream/OStream` 是内存流抽象，让参数/返回值在插件二进制间安全传递；
- 执行带异常兜底，未注册/异常返回失败，重复注册被拒绝。
