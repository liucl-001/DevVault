# 01 · 项目定位与全景：为什么一个切片软件需要一个插件框架

## 1.1 一句话定位

`OpenPlugins` 是面向 **AnycubicSlicerNext**（纵维立方 Anycubic 的 3D 打印切片软件）的**插件化基础库**。它不提供业务功能，而是提供"插件开发、部署、运行"所需的全部基础设施，让功能以独立、可扩展、可动态加载的插件形式长在主程序上。

仓库 README 的定位描述是：

> OpenPlugins 是一个为 AnycubicSlicerNext 提供插件化基础功能的开源库。该项目通过提供插件开发所需的基础功能模块，简化了插件化开发流程，使开发者能够更便捷地构建和集成插件。

## 1.2 为什么要插件化

桌面应用（尤其像切片软件这种功能持续膨胀的工具类产品）从"单体"走向"插件化"，通常有四个真实动因，OpenPlugins 也恰好逐一对应：

| 动因 | 落到 OpenPlugins 的对应能力 |
| ---- | ---- |
| **功能解耦**：核心与业务互不侵入，各自独立演进 | 模块化插件架构：清晰插件接口，独立开发/部署/管理 |
| **动态扩展**：新增功能不必重新发版整个应用 | 插件包动态加载/卸载，`*.zip` 包即插即用 |
| **协议统一**：插件之间要能可靠地互相调用 | 基于内存流的统一通信协议 + 事件驱动模型 |
| **界面与技术栈灵活**：部分功能需要 Web 技术实现 | 内置 `wxWebView` + Web API 路由 |

换句话说：核心程序只负责"框架与宿主"，业务能力交给插件。这既是工程组织上的选择，也是发布形态上的选择——**插件以独立包分发，可独立签名、校验、升级**。

## 1.3 技术栈全景

通读源码后，技术栈可以精确地拆成下面这张表（均为源码或 CMake 中可核实的依赖）：

| 层次 | 技术 | 用途 |
| ---- | ---- | ---- |
| 语言 | **C++20**（`CMAKE_CXX_STANDARD 20`，关闭扩展） | 全库统一标准 |
| 构建 | CMake ≥3.20，`CMakePresets.json` + 自定义 `cmake/*.cmake` 宏体系 | 跨平台构建、目标生成、安装 |
| GUI 框架 | **wxWidgets 3.3**（core/base/adv；`find_package CONFIG COMPONENTS core base adv`，管理器另需 xrc） | 主窗口、事件、资源、翻译 |
| 序列化 | **iguana**（`REFLECTION` 宏 + `read_json/to_json`） | 结构体 <-> JSON |
| 日志 | **spdlog** + **fmt**，封装为 `easy_log` | 分级日志、按日滚动、UDP 输出 |
| JSON 数据 | **nlohmann/json**、**Boost.JSON**、iguana | 不同场景的 JSON 处理 |
| 元编程/预处理 | **Boost.Preprocessor**、Boost.LexicalCast、Boost.ScopeExit、Boost.Nowide | 宏、类型转换、RAII、编码 |
| 密码学 | **OpenSSL**（EVP：AES-256-CBC + PBKDF2；RSA） | 插件包签名/加密、配置加密 |
| 网络 | **libcurl**（`CURL::libcurl`，`find_package(CURL 8.4.0 REQUIRED)`） | 插件网络能力 |
| 其它第三方 | **tree-sitter**（示例 Lua 插件用）、GoogleTest、Google Benchmark | 解析、测试、基准 |

值得注意的工程选择：仓库把 fmt、spdlog、iguana、nlohmann、tree-sitter **直接以源码形式放进 `3rdparty/`**（`add_subdirectory` 编译），而不是走包管理器——这与"工具链纯净、依赖可控"的取向一致，也符合国内网络环境下减少拉取失败风险的实际诉求。

## 1.4 仓库目录地图

```
open-plugins/
├── 3rdparty/            # fmt、spdlog、iguana、nlohmann、tree-sitter（源码编译）
├── WebView/             # wxWebView 跨平台封装（Edge/WebKit/Chromium）
├── cmake/               # 构建宏体系（basic/build/generate/subdir + 模板）
├── docs/                # how_to_build / create_plugin / directory / mechanism / contributing
├── easy_log/            # 日志封装（spdlog）+ 调用栈/符号化
├── instrument/          # 崩溃与堆栈符号化（msw/unix 分平台）
├── plugins/             # 测试插件（app/tabbook/utility/luatest，仅测试用，默认不编译）
├── plugins_base/        # 插件契约层：接口、元数据、流、函数包装、i18n
├── plugins_manager/     # 运行时核心：加载、生命周期、路由、包校验、XRC、配置
├── plugins_sdk/         # 开发者 SDK：event 事件、webview API、constant、communication
├── resources/           # 资源（common.hxx 公共定义）
├── Test/                # 单元测试（ENABLE_TEST / ENABLE_GTEST）
├── Bench/               # 基准测试（ENABLE_BENCH，google benchmark）
├── utility/             # 编解码、加密、JSON、文件、字符串工具
├── CMakeLists.txt       # 顶层：全局配置 + 子目录装配
└── CMakePresets.json    # macOS(Xcode/Ninja) / Windows(VS2019) / Linux 预置
```

顶层 `CMakeLists.txt` 的装配顺序本身就说明了模块依赖关系：

```cmake
include_directories(${CMAKE_SOURCE_DIR}/3rdparty)
option(ENABLE_WEBVIEW "Enable WebView WebKit" ON)
if(ENABLE_WEBVIEW)
    add_subdirs(WebView)
endif()
add_subdirs(3rdparty easy_log utility resources instrument)
find_package(wxWidgets 3.3 CONFIG COMPONENTS core base)
if(wxWidgets_FOUND)
    add_subdirs(plugins_base plugins_sdk plugins plugins_manager)
endif()
add_subdirGTEST(Test)
add_subdirBench(Bench)
```

几个值得注意的点：

- **WebView 是可选开关**（`ENABLE_WEBVIEW`，默认 ON）；
- **整个插件体系以 wxWidgets 为前提**——找不到 wxWidgets 3.3 就不编译插件相关模块；
- **测试（Test/Bench）是独立开关**（`ENABLE_TEST` / `ENABLE_GTEST` / `ENABLE_BENCH`），默认关闭；
- `ENABLE_WEBVIEW` 关闭时 WebView 相关能力不可用，这与"wxWebView 默认 wxWidgets 自带的太老、不方便定制"（`docs/directory.md`）的动机直接相关。

## 1.5 平台与构建形态

`CMakePresets.json` 为三个平台准备了可继承的 base preset：

| 平台 | 生成器 | 说明 |
| ---- | ---- | ---- |
| macOS（arm64 / x86_64） | Ninja（标注"XCode build"） | `macos_base_arm64` / `macos_base_x8664`，preset 设部署目标 11.3（顶层 CMake fallback 11.5），禁用代码签名 |
| Windows | Visual Studio 16 2019（host=x64） | `msvc_base`，MSVC 下全库开 `/utf-8` |
| Linux | Unix Makefiles | `linux_base`（面向插件作者的 `docs/create_plugin.md` 注明 Linux 未测试） |

构建流程（`docs/how_to_build.md`）是典型的"依赖先行 + preset 继承"：

1. 先编译 AnycubicSlicerNext 的 deps 目录（产出 wxWidgets、OpenSSL、curl 等安装树）；
2. 创建 `CMakeUserPresets.json`，`inherits` 平台 base preset，并配置 `CMAKE_PREFIX_PATH` 指向 deps 安装目录、`ENABLE_TEST/ENABLE_GTEST` 等开关；
3. `cmake --preset <name>` 配置，`cmake --build` 编译。

采用 **Mulan PSL v2**（木兰宽松许可证第二版，见 `LICENSE`），允许商用、修改、分发，与本仓库"开源基础库、欢迎社区贡献"的定位一致。

## 本章要点

- OpenPlugins 是切片软件的基础设施层，**不含业务**，只提供插件化的"运行时 + SDK"；
- 技术栈为 C++20 + wxWidgets 3.3 + CMake，序列化用 iguana、日志用 spdlog/fmt、密码学用 OpenSSL、网络用 libcurl；
- 第三方依赖以源码进 `3rdparty/`，构建全平台预设化、测试/基准独立开关；
- 后续章节从架构分层切入，逐层深入契约、运行时、通信与工程体系。
