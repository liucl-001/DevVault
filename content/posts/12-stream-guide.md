# 桌面串流全栈实战 · 导读与术语表

> 一套完整、自包含的 Windows 桌面串流系统实现讲解，拆成十篇逐层讲透。
> 技术主线：**屏幕采集 → HEVC 硬件编码 → RTP/UDP 传输 → 硬件解码 → SDL/Qt 上屏**。
>
> **本文不依赖任何特定工程源码**：文中的分层、代码片段均为可直接照抄或改编的
> **参考实现**，你可以完全按本系列从头写出一套可运行的系统。
>
> 指标基线：**首帧 ≤ 50ms，端到端 ≤ 100ms**，局域网 / 家用 WiFi 下不花屏、不白屏、不绿屏。

## 术语表

按主题分组。每组一张表（术语 | 含义）。这是后续十篇的**共同语言**。

### A. 视频基础

| 术语 | 含义 |
|---|---|
| **帧（Frame）** | 一张完整图像。视频 = 一串连续帧。 |
| **I 帧 / 关键帧（Keyframe / IDR）** | 可独立解码的完整帧，不依赖其它帧。解码必须从它开始。 |
| **P 帧 / B 帧** | P 帧依赖前一帧（参考帧）；B 帧依赖前后两帧。B 帧引入重排序延迟，实时流通常关掉。 |
| **IDR** | 一种特殊 I 帧（即时刷新），后续所有帧都不再引用它之前任何帧。是"断点重入"的锚点。 |
| **GOP** | 两个关键帧之间的帧组。GOP 越大，同码率画质越好，但出错后恢复越慢。 |
| **SPS / PPS** | HEVC/H.264 的参数集 NAL：声明分辨率、档次、熵编码方式等。解码任何帧前必须先有它。 |
| **NAL / annexb** | NAL = 网络抽象层单元，HEVC 码流的最小单元；annexb 是用 `00 00 01` 起始码分隔 NAL 的封装方式。 |
| **SEI** | 辅助增强信息 NAL（type 39/40），携带非解码必需的元数据（时间戳等），解码器自动忽略。 |
| **PTS / DTS** | 显示时间戳 / 解码时间戳。无 B 帧时两者相等。 |
| **码率（kbps）** | 每秒传输的比特数。码率 ↑ 画质 ↑ 带宽/延迟成本 ↑。 |

### B. FFmpeg 核心对象与调用模型

| 术语 | 含义 |
|---|---|
| **AVFormatContext** | 容器/格式层：封装一条流（文件或网络），管理若干 AVStream。 |
| **AVStream** | 一条流（一路视频/音频），携带 codecpar（编码参数）。 |
| **AVCodec** | 编解码器描述（哪个厂商、哪个格式），`avcodec_find_*` 查找。 |
| **AVCodecContext** | 编解码上下文：真正干活的引擎，含尺寸/像素格式/hw_device_ctx 等。 |
| **AVFrame** | 未压缩的原始图像（解码输出 / 编码输入），可能引用 GPU 硬件帧。 |
| **AVPacket** | 已压缩的码流数据（编码输出 / 解码输入）。 |
| **send / receive** | `avcodec_send_frame/send_packet` + `avcodec_receive_packet/receive_frame` 的异步编解码对。 |
| **EAGAIN / EINVAL** | send/receive 的返回码：EAGAIN=缓冲未就绪（正常，继续喂即可）；EINVAL=参数错误或需 drain。 |
| **demuxer / muxer** | 解封装器（读流，如 sdp）/ 封装器（写流，如 rtp）。 |
| **extradata** | 编码参数带外数据（如 HEVC 的 SPS/PPS），随参数集传入。 |
| **swscale（sws_scale）** | FFmpeg 软件像素格式/尺寸转换器（如 NV12→RGB）。 |

### C. 硬件加速

| 术语 | 含义 |
|---|---|
| **hw_device_ctx** | `AVHWDeviceContext`，挂在编解码上下文上，告诉编解码器用哪个 GPU 设备。 |
| **hw_frames_ctx** | `AVHWFramesContext`，硬件帧池：定义帧的硬件格式与内部软件格式。 |
| **AV_HWDEVICE_TYPE_*** | 硬件类型枚举：D3D11VA / QSV / CUDA / … |
| **硬件帧** | `AVFrame.data[0]` 是 GPU 纹理指针（如 `ID3D11Texture2D*`），不是 CPU 数据。 |
| **D3D11VA** | D3D11 视频加速，Windows 上 FFmpeg 硬件编解码的基础设备类型。 |
| **NVENC / QSV / AMF** | 三大 GPU 编码器：NVIDIA NVENC、Intel QSV（基于 oneVPL）、AMD AMF。 |
| **CUVID / NVDEC** | NVIDIA 的硬解方案：CUVID（旧）/ NVDEC（新）。 |
| **hevc_nvenc / hevc_qsv / hevc_amf** | FFmpeg 编码器名（按 GPU 厂商选）。 |
| **hevc_cuvid / hevc_nvdec / hevc_d3d11va** | FFmpeg 解码器名。 |
| **oneVPL** | Intel 的视频处理库，QSV 的现代实现。 |

### D. Windows 屏幕采集

| 术语 | 含义 |
|---|---|
| **DXGI** | DirectX 图形基础设施，负责显示器/交换链管理。 |
| **Desktop Duplication** | DXGI 的桌面复制 API，直接从桌面合成器拿帧（最快、可 GPU 直通），锁屏不可用。 |
| **GDI / BitBlt** | 传统位图拷贝抓屏。存在的原因：锁屏/登录界面（安全桌面）DXGI 不可用，只能靠它采集；CPU 拷贝、慢。 |
| **D3D11 / D3D11VA 设备** | 与 GPU 打交道的底层设备对象；采集与编码共享它实现零拷贝。 |
| **BGRA / NV12** | 像素格式：BGRA=32 位带透明通道；NV12=半平面 YUV（广泛用于硬件编解码）。 |
| **锁屏 / 安全桌面 / Winlogon** | 锁屏/登录界面运行在独立的"安全桌面"，抓它需特权 + 切换桌面。 |
| **DPI 缩放** | 高分辨率屏幕的逻辑/物理像素换算（如 125%）。 |
| **WARP** | D3D11 的软件渲染器，无 GPU 时兜底。 |
| **WTS API** | Windows Terminal Services：查询会话锁定状态、活动会话、用户名（锁屏检测的依据）。 |
| **Session（会话）** | Windows 会话（控制台 / RDP / Session 3 等）。锁屏后进程落入独立会话，采集安全桌面需切换。 |

### E. 传输与反馈

| 术语 | 含义 |
|---|---|
| **RTP / RTCP / RTSP** | RTP=媒体数据承载；RTCP=媒体质量反馈（SR/SR、PLI）；RTSP=会话控制（本项目不用）。 |
| **SDP** | 会话描述格式，描述媒体流（编码、端口、PT 映射）。接收端靠它才能解析动态 PT。 |
| **SSRC** | RTP 流标识符。 |
| **PT（payload type）** | RTP 载荷类型。HEVC 无静态 PT，用动态值（本项目 96）。 |
| **FU-A** | HEVC over RTP 的分片单元：大帧切成多个 RTP 包传输。 |
| **pkt_size / MTU** | RTP 分片粒度 / 网络最大传输单元。 |
| **UDP / 连接式 UDP（connect=1）** | 无连接 UDP vs 连接式 UDP（性能好、可感知对端不可达）。 |
| **PLI（RFC 4585 / PSFB）** | Picture Loss Indication：接收端请求"立刻给我一个 IDR"的标准 RTCP 消息。 |
| **墙钟 / 时钟偏移 / RTT** | 墙上时钟毫秒 / 两端时钟差 / 往返时间。测端到端延迟要先扣除时钟偏移。 |
| **AU（接入单元）** | 同一 RTP 时间戳的全部 NAL（即一帧）。解码器要求参数集先于 VCL 帧。 |
| **RR（接收端报告）** | RTCP 中收流方发的报告（丢包计数 / jitter / LSR）。本项目无码率自适应故暂未用。 |
| **jitter buffer（抖动缓冲）** | 按 RTP 序列号排乱序的小窗口。低延迟关键：窗口要小、超时即丢。 |
| **STAP-A** | HEVC over RTP 的聚合单元，把多个小 NAL（如 SPS/PPS/SEI）合成一个 RTP 包。 |

### F. 显示（SDL / Qt）

| 术语 | 含义 |
|---|---|
| **SDL** | 跨平台图形/输入库，本项目用它的 D3D11 渲染器做上屏。 |
| **SDL_CreateWindowFrom** | 让 SDL 绑定一个外部原生窗口（如 Qt 的 HWND），只接管其渲染。 |
| **STREAMING 纹理** | SDL 中"每帧更新内容"的纹理访问模式。 |
| **交换链 / ResizeBuffers** | D3D11 的显示缓冲重建机制；窗口缩放时靠它避免黑屏。 |
| **QWidget / HWND** | Qt 控件 / Windows 原生窗口句柄。 |
| **WA_PaintOnScreen / WA_NativeWindow** | Qt 属性：让渲染直写原生表面 / 强制成为原生窗口（SDL 嵌入的前提）。 |
| **三缓冲 / present** | 多块帧槽轮转 + 渲染提交，解码与渲染线程解耦、零拷贝。 |
| **present** | 把一帧提交到屏幕渲染（耗时、放渲染线程）。 |

### G. 自定义协议

| 术语 | 含义 |
|---|---|
| **控制面** | 与媒体分离的策略通道（心跳、帧率协商、暂停等）。 |
| **magic / version / seq** | 私有协议头字段：防串包 / 版本演进 / 序号。 |

## 全链路速览

```
端口：数据面 RTP/UDP 8554 · RTCP 9560 · 私有控制面 UDP 8555
延迟预算：采集 DXGI(≤8ms) + 编码(≤8ms) + 网络(1~3ms)
        + 接收/排序(≤4ms) + 解码(≤5ms) + 渲染(≤1帧) ≈ 40~60ms
首帧：连接(≈5ms) + 起推 IDR(≈10ms) + 收齐(≈16ms) ≈ 30~50ms
```
